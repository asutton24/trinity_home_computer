Project Trinity Specifications:

Memory map:
0000-7FFF: User ram
8000-895F: VRAM
9000: Video select byte
9001: clock byte (ticks every 1/60 seconds)
9002: Bell byte (bell will sound when this is non-zero
9003: ASCII code of last key pressed
9004: Keyboard control byte (1 if any key is pressed)
9005: Joystick 0 status byte (arrow keys and control key, XXXUDLRC)
9006: Joystick 1 status byte (arrow keys and control key, XXXUDLRC)
9007: Byte visible from tape
9008: Tape counter (will be incremented every time a new byte is made visible)
9009: Tape player on/off (zero for off, non-zero for on)
C000-FFFF: System rom

Video Modes:

Project Trinity has a 320 by 240 output which corresponds to 40 by 30 characters
or 80 by 60 subpixels, all video data is stored in VRAM

Mode 0:

Text Mode, each pair of two bytes corresponds to a 8 by 8 location on the screen.
The first byte has the background color in the upper nibble and foreground color
in the lower nibble. The second byte contains the code of the character to be
displayed in that location. The first pair corresponds to the top left position
with the following pairs moving right across the screen and down when a row is
complete.

Mode 1:

Graphics mode, each pair of two bytes corresponds to an 8 by 8 location on the screen.
They are laid out in the same order as in text mode. Each 8 by 8 location is split into
four 4 by 4 subpixels. The first byte sets the color of the upper two subpixels while
the second sets the color of the lower two subpixels. In both the upper nibble corresponds
to the left subpixel while the lower nibble corresponds to the right subpixel.

Mode 2:

Mixed mode:

The first 26 rows are in graphics mode while the remaining 4 are in text mode.





CPU Specs:

Registers: a, 8 bit accumulator; b and c, 8 bit general purpose registers;
i, 8 bit index register; pc, 16 bit program counter; sp, 16 bit stack pointer

Flags:
1 bit zero flag (invoked when a result is 0); 1 bit carry flag

Execution starts at address specified in FFFE-FFFF

The CPU runs at 1,000,000 instructions per second

Addressing modes:

imp: no operand is used. Ex sec

a: the a register is used as the operand. Ex lsr a

b: the b register is used as the operand. Ex adc b

c: the c register is used as the operand. Ex and c

i: the i register is used as the operand. Ex inc i

imd: The byte following the opcode is used as the operand. Ex xor #$01

abs: The byte at the address specified by abs is used. Ex ora $1000

abs,i: The byte at the address specified by abs plus i is used. Ex lda $2002,i

(ind): A pointer stored at ind is used to fetch the operand. Ex ldb ($0001)

(ind),i: The pointer stored at ind plus i is used as the operand Ex ldc ($FF00),i
